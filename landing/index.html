Agent Gateway

A personal bridge between your Telegram account and your AI agent. You deploy it on a host you control and pay for. Only chats you put in a Telegram folder named Agent are visible to the agent. Your session never leaves your instance.

How it works01

It logs in as you, and shows your agent only one folder.

Session

MTProto as you, not a bot

Uses a Telegram user session (Telethon), so it can read the DMs and groups you allow. The Bot API cannot do this for personal chats.

Allowlist

The folder is the allowlist

Create a folder called Agent in Telegram and add chats. Remove a chat to revoke access. No bots to invite.

Agent

Your agent gets an API token

Your AI calls /v1 with a bearer token. It never receives your Telegram session or api_hash.

Host

You are the host

No company fleet, no shared multi-tenant box. Your session lives only on the instance you deployed. Nothing runs on anyone else’s servers.

Setup02

Deploy first. Your server walks you through the rest.

  1. 01Fork
  2. 02Deploy
  3. 03Open your server

  1. Copy it to your GitHub

    Log in to GitHub (free account at github.com/signup), open telegram-agent-gateway and click Fork → Create fork. Your server runs from your copy, so nobody else can change it.

  2. Deploy it. You pay the platform.

    We recommend Render: sign in at dashboard.render.com with GitHub, pick your copy, and it reads the repo’s render.yaml, so the disk and health check are set up for you. Or hand it to your coding agent with the prompt below.

    • On Render choose New → Blueprint, not “New Web Service” (that one skips the disk).
    • Give Render’s GitHub app access to only your copy.
    • If the Blueprint Path box is empty, click it and choose render.yaml.
    • Click Deploy Blueprint and wait for Live (3–5 minutes).
    Deploy to Render Fly / VPS / Docker guide
    Needs
    An always-on plan and a persistent disk mounted at /data. Without the disk you lose the Telegram login on every restart.
    Cost
    Render: Starter plan about $7 a month plus about $0.25 for the 1 GB disk. The free plan has no disk.
    Run exactly one instance No replicas, no scaling, no zero-downtime deploys. Two copies on one login make Telegram end it, and you have to log in again. On Fly, launch with --ha=false.

  3. Open your server’s address

    Open the https:// address your host gives you, e.g. https://your-app.onrender.com. On Render it’s at the top of the service page. Never a bare IP or http:// address: the server refuses to run setup without HTTPS. It opens a setup page that takes you through everything, one screen at a time:

    • Start. Press Start. Your browser becomes the owner, and setup closes to everyone else. Do this right after the deploy finishes.
    • Telegram keys. It sends you to my.telegram.org, shows exactly where to click, and you paste api_id and api_hash.
    • Log in. Scan a QR code with the Telegram app. 2FA works.
    • Agent folder. Make a Telegram folder called Agent and add the chats your agent may read. The page checks it.
    • Connect your agent. You get a token and a ready-to-paste block for Claude, Grok or your own agent, plus a test button.

    Your keys and your Telegram login go straight to your server and stay there.

    Emergency stop Telegram → Settings → Devices → end the gateway’s session. Your agent loses access at once.

What this is not04

Not Telegram’s, and not a service.

Independent

Not an official Telegram product

An independent open-source gateway built on Telegram’s public Client API. Use at your own risk and follow Telegram’s API terms.

Self-hosted

Not a hosted SaaS for your DMs

There is no central “sign up and we hold your session” service. This page only explains. Login happens on your own deploy.
